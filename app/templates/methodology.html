Required contract clauses

Each clause in this list is checked against vendor evidence by the evidence validator. The result uses the same statuses as a claim. Verified means a reviewer confirmed current supporting evidence from a source other than the vendor. That is the assured state. Self-attested means the vendor's own statement. Missing, conflicting, expired, and not reviewed stay distinct. A gap is shown to the reviewer. It does not change the inherent score or the residual tier, it does not add an escalation rule, and it does not block a human decision.

Intake questionnaire · {{ questionnaire_version }}

The public form asks the questions that can change the score or the review route. Model training is asked only when AI use is not none. If that answer is left off the submission, it is stored as no and the reviewer package marks it not applicable. An answer that is actually submitted is kept. The decisions-affecting-people question is always asked, because HR-001 does not depend on AI use.

A vendor trust-center URL is optional. Leave fetch at no and the application does not open the page. SOC, privacy, and security choices are pasted metadata. Each choice becomes an evidence record, and the evidence validator assigns the status. One SOC choice is cited for authentication and for logging, and each claim is scored on its own. Choosing fetch performs one HTTP GET and stores an excerpt for review. That page is vendor-published material. The validator marks it not yet reviewed. It is not verified evidence, it does not change evidence confidence, and it does not approve the vendor. A URL by itself adds no scored record.

The form also asks how the vendor relationship is moving and which way the requester expects residual exposure to move. Those answers, and an optional note, are context for a person. They are not scored. They do not change the residual tier, the disposition, or the control mappings. Leaving them blank means not provided. It is not treated as a safeguard.

The reviewer package is a JSON file and a text summary for one vendor. It includes the intake answers, direction context when the intake collected it, the evaluation, the policy outcome, required-clause statuses, an evidence summary, and the human decision when one is recorded, including self-reported handling minutes, self-reported rework minutes, self-reported manual touches, and self-reported handoffs when that decision has them. A blank rework field says rework time was not reported. A blank manual-touches field says manual touches were not reported. A blank handoffs field says handoffs were not reported. It is a handoff, not a disposition. The question text is in app/data/intake_questionnaire.json.

Control mappings

The control mappings page lists every entry in mapping set {{ mapping_set_version }} ({{ mapping_count }} in the current library). The set includes a selected NIST SP 800-53 Rev. 5 subset, four ISO/IEC 27001:2022 Annex A controls, and four ISO/IEC 42001:2023 Annex A controls. NIST identifiers and titles were checked against the NIST control catalog materials. ISO/IEC 27001:2022 Annex A identifiers and short titles were checked against the ANSI National Accreditation Board annex comparison. ISO/IEC 42001:2023 short titles were cross-checked against public Annex A lists. The ISO preview names Annex A and does not list each control title. The ISO entries are draft portfolio review prompts. Applicability and rationale remain draft. The page does not present conformity, certification, or cross-framework equivalence. See docs/control-mapping-methodology.md.

Observed workflow metrics · definition {{ observed.definition_version }}

Counted from the local register

Assessment volume counts saved assessments. Persisted dispositions count human decisions stored on those assessments. A public /try/ run that is not saved is in neither count. Open remediation, residual tier, claim evidence, and clause evidence are also counts of stored rows. Intake-to-disposition cycle time is elapsed clock time between two workflow events. Self-reported human handling time is the optional minutes a person enters when recording a disposition. Self-reported rework time is a separate optional number for minutes spent redoing work after a first pass. Self-reported manual touches are a separate optional count of human touchpoints on that assessment. Self-reported handoffs are a separate optional count of times the assessment was handed between people or queues before disposition. Each of those four figures is the median of the current decision rows that include that number. Blank rows stay out of that median. Those numbers are not a timer, they are not checked against an identity system, and they are not elapsed cycle time. Rework minutes are not handling minutes. Manual touches are not handling minutes and not rework minutes. Handoffs are not handling minutes, not rework minutes, and not manual touches. The monthly assessment rate is separate from all four. It counts current decision rows, one per saved risk, by the decided_at timestamp already stored on that row. The window is the closed 30 days ending at the latest readable timestamp, and both ends are included. A number appears only when the earliest readable timestamp is at least 30 days earlier, which means the register covers that full window. Otherwise the card says Not measured. A short span is not turned into a monthly rate. An older decision event is not counted. An unsaved public try is not counted. Saved assessments with no decision are not counted. The rate is not handling minutes, not rework minutes, not manual touches, not handoffs, not authenticated effort, and not elapsed cycle time. It is not the modeled assessments-per-month input. Authenticated effort is a separate optional number of whole minutes a signed-in reviewer entered on a disposition. Signed-in means the request passed the demo password gate. The public try and import forms do not ask for it, and a request that did not pass the gate cannot store it. The application does not time the session, does not scale a partial number up to a month, and does not fill a blank with zero or with handling minutes. The headline figure is the median of current decision rows that store a number. Blank rows stay out of that median. When none store a number, the card says Not measured. These minutes are not self-reported handling time, not rework time, not manual touches, not handoffs, not the monthly assessment rate, not cash savings, and not elapsed cycle time. Cash savings are a separate optional number of whole dollars a signed-in reviewer entered on a disposition when a spending reduction was known. Signed-in means the request passed the demo password gate. The public try and import forms do not ask for it, and a request that did not pass the gate cannot store it. The application does not multiply handling minutes, rework minutes, manual touches, handoffs, authenticated effort, or the monthly assessment rate by a wage, and it does not read the illustrative labor rate. The headline figure is the median of current decision rows that store a number. Blank rows stay out of that median. Zero is a reported zero. When none store a number, the card says Not measured. These dollars are not self-reported handling time, not rework time, not manual touches, not handoffs, not authenticated effort, not the monthly assessment rate, not elapsed cycle time, and not avoided-incident value. Avoided-incident value is a modeled assumption on its own card. It says Not measured while incident_cost and avoided_incident_count are null in the versioned assumptions. A value appears only when both are set. It is not an observed register figure, not cash savings, and not an input to calculate_cost(). The public try form and file import cannot supply it. The same function, app/services/workflow_metrics.py, supplies the dashboard and this page. On these pages the rows are this browser's sandbox plus any saved row with no sandbox id. Another browser's sandbox is not included. Definition 9 is unchanged. A direct call with no scope still reads the whole table. Saving or deleting a local risk in this scope changes these figures. An empty scope still says Not measured where a figure was not recorded. It leaves the illustrative formula below unchanged.

Illustrative assumptions

The observed counts in the previous section stay out of these inputs. Gross capacity = assessments/month × (baseline handling hours − assisted handling hours).

Net capacity = gross capacity − added review effort − monthly maintenance.

Modeled result: {{ cost.gross_capacity_hours }} gross hours (${{ '%.2f'|format(cost.gross_capacity_value) }} gross value); subtract {{ cost.review_effort_hours }} hours of review and {{ cost.maintenance_hours }} hours of maintenance to produce {{ cost.net_capacity_hours }} net modeled capacity hours (${{ '%.2f'|format(cost.net_capacity_value) }} modeled value).

Inputs: {{ cost.assumptions.assessments_per_month|int }} modeled assessments per month (an assumption, not the saved assessment volume and not the observed monthly assessment rate); baseline {{ cost.assumptions.baseline_handling_hours_per_assessment }} hours and assisted {{ cost.assumptions.assisted_handling_hours_per_assessment }} hours per assessment; review {{ cost.assumptions.review_hours_per_assessment }} hours per assessment; maintenance {{ cost.assumptions.monthly_maintenance_hours }} hours per month; labor rate ${{ cost.assumptions.loaded_hourly_labor_rate }} per hour.

This value is labor capacity, not cash savings. This formula does not calculate a spending reduction. Observed cash savings stay on the panel above, and only when a signed-in reviewer entered whole dollars. One-time development cost is unknown and excluded. Self-reported handling minutes are not inputs to this formula. Self-reported rework minutes are not inputs to this formula. Self-reported manual touches are not inputs to this formula. Self-reported handoffs are not inputs to this formula. The observed monthly assessment rate is not an input to this formula. Authenticated effort minutes are not inputs to this formula. Cash savings dollars are not inputs to this formula. Avoided-incident value is not an input to this formula. Workflow timestamps are elapsed time, not handling time, not rework time, not a manual-touch count, not a handoff count, not authenticated effort, not cash savings, and not avoided-incident value.

How the event chain is checked

verify_event_chain() in app/services/event_chain.py checks one sequence. It does not import Flask. The shared sequence is every workflow event with no sandbox id, in event_id order. Each browser sandbox is its own sequence, also in event_id order. The canonical JSON contains event_id, risk_id, event_type, detail, occurred_at, prev_hash, and chain_origin. Keys are sorted. The sandbox id is not in that JSON. The digest is lowercase SHA-256 hex. The first event in a sequence uses 64 zeros as prev_hash. A later event uses the previous hash in that same sequence. A row written by the application has chain_origin appended. A row that already existed when the chain was added has chain_origin chained_after_the_fact. Startup hashes those rows once and then leaves them alone, so a later edit is not given a fresh hash. The check also compares the last row in a sequence with that sequence's tip. Deleting a later row leaves the next stored row, or that tip, as the first break. Deleting every row and the tip leaves an empty log, and an empty log checks as intact. Deleting one stale sandbox removes that sequence only. The other sequences are not rewritten. Rebuilding every hash produces a chain that checks as intact. The result above checks every sequence. It is intact only when each one is intact. It is separate from observed workflow metrics and from calculate_cost().
