Risk and evidence

The risk engine uses illustrative rule set {{ risk_model_version }} from app/data/risk_rules.json. It separates inherent score, evidence confidence, residual tier, configured escalation, and the org-policy outcome. Unknown required inputs can make the tier undetermined; a low number never approves a vendor. A blank answer opens a deeper assessment only when that blank could hide a configured mandatory condition. Point values are unchanged from rule set 0.2.0.

Evidence status is derived from reviewed evidence records using evidence policy {{ evidence_policy_version }}. Missing evidence means not demonstrated, not confirmed failure. The same rules check each required contract clause. See scenario examples and saved local risks.

Required contract clauses

Each clause in this list is checked against vendor evidence by the evidence validator. The result uses the same statuses as a claim. Verified means a reviewer confirmed current supporting evidence from a source other than the vendor. That is the assured state. Self-attested means the vendor's own statement. Missing, conflicting, expired, and not reviewed stay distinct. A gap is shown to the reviewer. It does not change the inherent score or the residual tier, it does not add an escalation rule, and it does not block a human decision.

Control mappings

No ISO framework mappings, certification conclusions, or cross-framework equivalence claims are presented. See docs/control-mapping-methodology.md.
